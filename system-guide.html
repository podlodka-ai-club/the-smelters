Operator Guide

How To Run The Multi-Agent Dev Assistant

This system takes a queue of failing-test tasks, creates an isolated git worktree per task, lets a Coder agent make a fix, and lets a Reviewer agent accept or reject the result. Everything is tracked through SQLite plus an append-only event log.

Core flow
ready running review closed
What matters operationally Run the system with .venv/bin/python so the agent modules resolve inside task worktrees and the fake or real agent entrypoints stay importable.
System Map

Who Does What

The pieces are intentionally narrow. That keeps the control loop easy to debug and lets you inspect one artifact at a time.

seed.py

Scans tasks/*.md, reads each task's Project: line, and inserts rows into tasks.db as ready.

orchestrator.py

Claims tasks, creates worktrees, runs Coder then Reviewer, and moves tasks to needs_fixes, closed, or failed.

printer.py / tui.py

Read-only monitoring layers over events.jsonl and tasks.db. They never mutate task state.

State Store

src/tracker.py owns SQLite CRUD, attempt counters, review notes, and the atomic claim_next_ready_task() transition.

Execution Layer

agents/runner.py spawns agent processes, enforces timeouts, and emits process-level events. The agents themselves stay small entrypoints.

Quick Start

Run It In Four Moves

Use the fake path first. It validates orchestration, eventing, retries, and monitoring before you spend tokens on the real API.

1. Create the environment 
uv venv
uv pip install -e ".[dev]"
2. Seed the task queue 
.venv/bin/python seed.py
3. Start the orchestrator 
.venv/bin/python orchestrator.py --watch
4. Watch the system 
.venv/bin/python printer.py
.venv/bin/python tui.py
Workflow

What Happens To One Task

Every task gets its own branch and worktree. Nothing is shared across task sandboxes except the central tracker and event log.

Claim

The orchestrator picks the lowest-id ready task and marks it running.

Isolate

A dedicated task-<id> worktree is created under worktrees/. The task record stores both branch and path.

Code

The Coder agent reads the spec, edits only inside the worktree, and prints a final JSON line describing the attempt.

Review

The Reviewer runs tests, inspects the diff, and emits a strict JSON verdict. Malformed output is treated as rejection.

Close Or Retry

If approved, the task closes. Otherwise it returns to ready with review notes until the attempt budget is exhausted.

Modes

Fake Mode vs Live Mode

Both modes use the same orchestrator. Only the agent entrypoints differ.

Fake Mode

Use FAKE_CODER and FAKE_REVIEWER scenarios to prove retries, crashes, malformed verdicts, and happy-path closes without touching the Claude API.

ok crash timeout reject malformed

Live Mode

Run the real SDK-backed agents only when ANTHROPIC_API_KEY is available and you want to validate an actual end-to-end bug-fix path.

ANTHROPIC_API_KEY=... .venv/bin/pytest -m live
Artifacts

Where To Look When Something Breaks

You rarely need to guess. Most failures leave a trace in one of these files or directories.

tasks.db

Source of truth for task status, attempts, worktree path, branch, and review notes.

events.jsonl

Append-only execution timeline. This is the fastest way to see whether the system failed in claim, worktree creation, Coder, Reviewer, or final state transition.

worktrees/task-<id>

Exact sandbox that the agent modified. Use it to inspect diffs, rerun tests, or compare against main.

tasks/*.md

Operator-facing task definitions. Each one names the failing test and the acceptance criteria that the Coder and Reviewer should obey.

Safety

Operational Rules

These are the constraints that keep the system predictable instead of “agentic” in the bad sense.

One task at a time

The orchestrator is intentionally serial. Concurrency is a future extension, not a hidden default.

One worktree per task

Edits are isolated by branch and path, which makes inspection, cleanup, and retries tractable.

Evidence before claims

Use .venv/bin/pytest, event logs, and task rows as evidence. Don’t infer success from “it probably worked.”

The current repository already supports fake-agent dry-runs, retry loops, malformed reviewer handling, printer/TUI monitoring, and a skip-safe live smoke test. The remaining unproven path is a real Claude API execution with a valid ANTHROPIC_API_KEY.
